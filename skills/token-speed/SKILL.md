---
name: token-speed
description: 查询 Codex Token 速度计的 t/s、缓存命中率和自动显示连接状态。
---

调用本插件 MCP 的 `token_speed_status` 工具查询状态。当前验证版使用 `token_speed_panel` 打开原生会话侧面板，由客户端管理布局，无需用户手动运行启动脚本或授予辅助功能定位权限。只有宿主实际显示并能更新数据，才算面板接入成功；HTML 预览和协议测试不能代替真实宿主验证。

解释指标时：t/s 是最近一次完整文本回复的日志窗口估算速度。工具调用或新请求缺完整计时时，保留同一聊天上一次有效速度并弱化，speedFresh=false；新聊天从未有有效速度时才显示 `--`。后续完整文本回复可更新测速，不能把历史值解释为当前请求速度。缓存命中率是会话累计缓存输入占比，继续独立更新，不能把上下文占用率解释成缓存命中率。

activity 的 generating 表示模型请求阶段，包含等待响应；tool 表示工具未全部返回；complete 为完成；idle 为闲置或取消。speedFresh=false 表示当前显示的是历史有效速度。呼吸只反馈阶段，不是逐 token 实时测速，减少动态效果开启时不呼吸。

模型或推理档位变化会清除旧速度，不跨配置借用历史值。speedReason 解释为何未更新；ambiguous-window 表示用量与计时无法可靠配对。speedUpdatedAt 是最近有效样本的日志时间，null 表示未知，不能当成当前时间。model / effort 表示速度适用配置。面板真实加载和日志估算精度分别验证，不以数字更新代表精确测速。

旧响应的重复用量不能覆盖较新请求的累计缓存；只有最新请求的重复记录可修订缓存。归档和取消归档会自动重新定位日志，同一文件保留历史读取状态；暂时缺失时指标未知，不能解释为缓存命中率为零。

若状态为 disconnected / waiting-session，建议重新打开一个本地聊天以重新发送选中会话事件；multiple-windows 需仅保留一个 Codex 主窗口，remote-session 表示远程日志不在本机。显示进程错误按工具返回报告，不自行修改 Codex 文件、安全策略或开调试端口。
